**Category-interchangeable shell with authored vocabulary (~5/10).** The token set is stock shadcn/Tailwind dark (`index.css:9-75`); Inter + JetBrains Mono are declared but never loaded (`document.fonts` empty → OS fallback everywhere); Lucide default icons; a dead second design system in `components/ui/MetricCard.tsx` referencing non-existent tokens. ## Overall Impression

A serious, restrained console with genuinely operator-shaped thinking underneath — executed in a generic template with a broken type stack, a layout bug that steals 8–10% of every viewport, and three places where the UI asserts green certainty the backend does not have. Single biggest opportunity: make every status provably sourced (kill hardcoded guarantees) and fix the phantom rail; those two changes move it from "template" to "terminal".

## What's Working

1. **Freshness as a first-class concept** — per-metric FreshnessIndicator, explicit READ-ONLY badge, `freshness: LIVE|STALE|UNKNOWN` threaded through API types, stated unknown≠zero intent.
2. **Real engineering hygiene in the chrome** — working skip link, visible focus rings, prefers-reduced-motion honored, sticky table headers, skeletons, zero horizontal overflow on all 8 routes at 390px, genuine mobile card list instead of a squeezed table.
3. **Operator-shaped IA** — Operations/Evidence/System grouping, ⌘K searching symbols and correlation IDs, Evidence maturity → Qualification gates chain, color-blind-safe chart palette with a documented rationale.

## Priority Issues

### [P0] Phantom left rail steals the layout on every viewport
- **What:** `Layout.tsx:74` mounts `<CommandPalette />` as a direct flex child; its trigger button becomes a 118×900px (desktop) / 38px (mobile) gutter. A second mount at `Layout.tsx:168` means two palette inputs and two ⌘K listeners — one keystroke opens two stacked modals.
- **Why:** 8–10% of width dead on every screen; reads as a rendering fault; focus stop #2.
- **Fix:** delete `Layout.tsx:74`; keep the top-bar mount (one line).
- **Suggested command:** `$impeccable layout`

### [P0] "Guarantees" are hardcoded green
- **What:** `System.tsx:96-102` — R4 Frozen / Fail-Closed / Reconciliation / Evidence Ledger all `ok: true` literal; only Read-Only and Fingerprint are sourced. At observation time the API reported reconciliation WARNING and 70 unacknowledged CRITICAL alerts.
- **Why:** a fail-closed trading console ends on four unwarranted green checks; UI asserts guarantees the backend does not verify.
- **Fix:** derive from endpoints; where no source exists render a neutral policy statement with `verified <time>` — never a green pass.
- **Suggested command:** `$impeccable harden`

### [P1] Status truthfulness: three freshness sources + undated timestamps
- **What:** `Overview.tsx:234-236` feeds one `account.timestamp` to all six cards (Risk showed green LIVE while its payload said UNKNOWN/2 days old); `FreshnessIndicator.tsx:16-26` takes icon from server freshness but label/color from client-side age (two truths that disagree; double-renders label); `Alerts.tsx:62`, `Events.tsx:120`, `Positions.tsx:294` render `toLocaleTimeString()` with no date — a 15-hour-old critical reads as now; the 24h `formatTimestamp` util exists and is unused.
- **Why:** the operator's core question "how old is this?" is answered inconsistently per screen; the most critical page answers worst.
- **Fix:** one freshness contract (server wins; timestamp only for relative age), per-datum timestamps, date+time on every alert/event.
- **Suggested command:** `$impeccable harden`

### [P1] Accessibility: unreadable text, overridden labels, unreachable rows
- **What:** muted text `#52525b` on `#09090b` = 2.57:1 at 9–11px (65/187 text nodes <11px on Risk; min 8px); `StatusBadge` `aria-label={variant}` makes a badge reading "LONG" announce "success" (~20 live regions per page re-firing each 5–10s poll); positions rows/cards `tabIndex:-1` → drawer unreachable by keyboard; two `<h1>` per page; mobile filter buttons 23px tall.
- **Why:** Sam cannot read labels, cannot reach the drawer, hears "success" instead of status.
- **Fix:** lift muted to ≥4.5:1 or reserve for ≥16px; drop aria-label overrides; tabIndex 0 + Enter/Space on rows; single h1; 44px touch targets.
- **Suggested command:** `$impeccable audit`

### [P2] Error and empty states are decorative; "no alerts" asserts normality
- **What:** `ErrorState.tsx` never imported; no page reads `isError`; `App.tsx:30` retry:1; `Alerts.tsx:129` renders "All systems operating normally" from `alerts.length === 0` (an empty array could be a failed endpoint); `useLiveStream` state consumed by nothing — the "live" WS is decoration over polling and fails 403 permanently.
- **Why:** operator cannot distinguish healthy / no data / dashboard broke.
- **Fix:** read isError per query, render ErrorState with retry, conditionally copy empty state, consume or remove the WS indicator.
- **Suggested command:** `$impeccable harden`

## Questions to Consider

1. If the Guarantees panel can show six green checks while the risk feed says CRITICAL and 70 unacknowledged reconnect failures stack, what exactly is it guaranteeing — the system, or the screenshot?
2. "LIVE" appears three ways on one screen (stream connected, data fresh, trading authorized). Which one is the operator betting on — and what happens when they bet wrong?
3. Why does a column titled "Reconciled ✓" mean "has a stop-loss"? What will an operator conclude when all rows are green and the banner above says 20 discrepancies?
4. You declared Inter + JetBrains Mono, a deuteranopia-safe palette, and a "premium institutional trading terminal" — but load no fonts and render in the OS fallback. Are you shipping a terminal, or a template that talks like one?
